01 · Gambaran Umum

Apa yang Akan Disiapkan.

SMTP adalah jalur yang digunakan COSMIC CMS untuk mengirim email dari alamat resmi hosting. Setelah SMTP aktif, sistem dapat mengirim undangan akun dan tautan verifikasi email.

COSMIC CMS→SMTP Hosting→Email Pengguna→Aktivasi Akun
FiturFungsi
Undangan penggunaAdmin baru menerima tautan untuk memverifikasi email dan membuat password sendiri.
Perubahan email superadminEmail baru tidak langsung aktif. Sistem mengirim tautan verifikasi lebih dahulu.
Kirim ulangSuperadmin dapat mengirim ulang undangan yang belum diterima atau sudah kedaluwarsa.
KeamananTautan memakai token sekali pakai dan memiliki masa berlaku.
Kondisi superadmin pertama: akun hasil seeder tetap dapat langsung login menggunakan email dan password dari file .env. Setelah login, ganti email bawaan dengan email operasional yang dapat diakses.

Yang perlu disiapkan

  • Akses cPanel atau panel hosting.
  • Satu akun email resmi, misalnya noreply@domainanda.com.
  • Host SMTP, port, username, dan password email.
  • Akses File Manager atau SSH ke folder aplikasi Laravel.
  • Domain production sudah memakai HTTPS.

02 · Membuat Email Hosting

Buat Akun Pengirim.

  1. Masuk ke cPanel menggunakan akun hosting.
  2. Buka menu Email Accounts atau Akun Email.
  3. Klik Create atau Buat.
  4. Pilih domain website COSMIC.
  5. Gunakan nama seperti noreply, system, atau admin. Contoh: noreply@cosmicfc.id.
  6. Buat password yang kuat dan simpan di password manager.
  7. Atur kapasitas mailbox secukupnya, lalu simpan.
Disarankan: gunakan akun email khusus sistem. Jangan menggunakan email pribadi dan jangan memakai password cPanel sebagai password SMTP.

Catat konfigurasi SMTP

Pada daftar akun email, klik Connect Devices, Set Up Mail Client, atau menu sejenis. Catat informasi berikut:

InformasiContoh
SMTP hostmail.cosmicfc.id
SMTP port STARTTLS587
SMTP port SSL/TLS465
UsernameAlamat email lengkap: noreply@cosmicfc.id
PasswordPassword akun email yang baru dibuat
Rahasia: password SMTP hanya ditulis di file .env. Jangan memasukkannya ke source code, GitHub, screenshot, atau dokumen publik.

03 · Memilih Port

Gunakan Konfigurasi yang Tepat.

Gunakan salah satu konfigurasi yang diberikan hosting. Pilihan yang paling umum adalah port 587.

Port 587 — Disarankan

Menggunakan koneksi SMTP dan meningkatkan keamanan melalui STARTTLS.

MAIL_SCHEME=smtp MAIL_PORT=587

Port 465

Menggunakan TLS sejak awal koneksi. Gunakan jika hosting secara khusus meminta SSL/TLS port 465.

MAIL_SCHEME=smtps MAIL_PORT=465
Jangan mencampur konfigurasi: port 587 biasanya menggunakan smtp, sedangkan port 465 menggunakan smtps. Jika ragu, mulai dari port 587.

Jika hosting hanya memberi port 25

Port 25 sering diblokir atau tidak menggunakan enkripsi yang memadai. Hubungi penyedia hosting dan minta konfigurasi SMTP aman port 587 atau 465.

Pastikan alamat pengirim sama

Beberapa hosting menolak pengiriman jika MAIL_FROM_ADDRESS berbeda dengan MAIL_USERNAME. Untuk pengaturan awal, gunakan alamat yang sama.

04 · Konfigurasi Laravel

Edit File .env Production.

  1. Buka File Manager cPanel.
  2. Masuk ke folder aplikasi COSMIC CMS.
  3. Aktifkan Show Hidden Files agar file .env terlihat.
  4. Buat salinan cadangan file .env sebelum mengubahnya.
  5. Edit bagian konfigurasi mail menggunakan data dari hosting.

Contoh port 587

MAIL_MAILER=smtp MAIL_SCHEME=smtp MAIL_HOST=mail.domainanda.com MAIL_PORT=587 MAIL_USERNAME=noreply@domainanda.com MAIL_PASSWORD="PASSWORD_EMAIL_ANDA" MAIL_FROM_ADDRESS=noreply@domainanda.com MAIL_FROM_NAME="COSMIC CMS"

Contoh port 465

MAIL_MAILER=smtp MAIL_SCHEME=smtps MAIL_HOST=mail.domainanda.com MAIL_PORT=465 MAIL_USERNAME=noreply@domainanda.com MAIL_PASSWORD="PASSWORD_EMAIL_ANDA" MAIL_FROM_ADDRESS=noreply@domainanda.com MAIL_FROM_NAME="COSMIC CMS"
Ganti semua contoh: ubah domain, username, dan password sesuai informasi SMTP hosting Anda. Tanda kutip pada password disarankan, terutama jika password memiliki karakter khusus.
Jangan gunakan: MAIL_MAILER=log pada production. Konfigurasi tersebut hanya menulis isi email ke log dan tidak mengirim email kepada pengguna.
5
05 · URL dan Cache

Pastikan Tautan Mengarah ke Domain Production.

Tautan aktivasi dan verifikasi dibuat berdasarkan alamat aplikasi. Karena itu, APP_URL harus memakai domain production, bukan localhost.

APP_ENV=production APP_DEBUG=false APP_URL=https://domainanda.com FORCE_HTTPS=true PUBLIC_ORIGIN=https://domainanda.com

Jika aplikasi dipasang pada subdomain, gunakan alamat lengkap, misalnya:

APP_URL=https://cosmic.domainanda.com PUBLIC_ORIGIN=https://cosmic.domainanda.com

Bersihkan cache konfigurasi

Setelah menyimpan .env, jalankan melalui Terminal cPanel atau SSH dari folder aplikasi:

php artisan optimize:clear php artisan config:cache php artisan route:cache php artisan view:cache
Penting: Laravel dapat tetap memakai konfigurasi lama jika cache belum dibersihkan. Selalu jalankan perintah di atas setelah mengubah SMTP atau domain.

Pastikan database terbaru

php artisan migrate --force

Perintah ini menambahkan kolom status undangan, email yang menunggu verifikasi, token, dan waktu kedaluwarsa.

06 · Pengujian SMTP

Uji dengan Akun Baru.

  1. Login sebagai superadmin.
  2. Buka menu Pengguna & Role / Kelola Akses.
  3. Klik Tambah Pengguna.
  4. Isi nama, alamat email yang benar-benar dapat Anda buka, role, dan status akun.
  5. Klik Kirim Undangan.
  6. Tunggu 1–5 menit lalu periksa Inbox, Spam, dan Promotions.
  7. Buka tombol Aktifkan Akun dari email.
  8. Buat password baru dan konfirmasi password.
  9. Login menggunakan alamat email dan password yang baru dibuat.

Hasil yang benar

  • Sebelum tautan dibuka, status akun adalah Menunggu Aktivasi.
  • Setelah aktivasi, status berubah menjadi Aktif & Terverifikasi.
  • Pengguna dapat login jika opsi Akun Aktif dinyalakan.
  • Password tidak pernah ditentukan atau diketahui oleh superadmin.
Berhasil: jika email diterima, tautan dapat dibuka, password dapat dibuat, dan akun dapat login, berarti SMTP dan mail verification sudah bekerja.
Belum menerima email? jangan langsung membuat akun kedua dengan alamat yang sama. Gunakan aksi Kirim Ulang Undangan pada akun tersebut setelah memperbaiki SMTP.

07 · Superadmin

Ganti Email Awal Deployment.

Akun superadmin dari seeder tetap dapat login. Setelah SMTP berhasil diuji, ganti email bawaan dengan email operasional yang aman.

  1. Login memakai SUPERADMIN_EMAIL dan SUPERADMIN_PASSWORD dari environment production.
  2. Buka menu profil akun dari bagian bawah sidebar.
  3. Pada Email login, masukkan email operasional baru.
  4. Masukkan password superadmin saat ini.
  5. Klik Simpan Profil.
  6. Buka Inbox email baru dan klik Verifikasi Email Baru.
  7. Setelah berhasil, login berikutnya menggunakan alamat email baru.

Perlindungan dari sistem

  • Email lama tetap aktif sampai email baru dikonfirmasi.
  • Jika email tidak diterima, gunakan Kirim ulang tautan.
  • Jika alamat salah, gunakan Batalkan perubahan.
  • Tautan email baru berlaku selama 60 menit.
  • Seeder berikutnya tidak mengembalikan email dan password ke nilai awal.
Setelah selesai: simpan kredensial superadmin di password manager. Jangan membagikannya melalui chat atau menuliskannya pada dokumen publik.

08 · Pemecahan Masalah

Jika Email Tidak Terkirim.

GejalaPenyebab yang mungkinSolusi
Connection refused / timeoutHost atau port salah; port diblokir hosting.Cocokkan data Connect Devices dan tanyakan port SMTP yang dibuka.
Authentication failedUsername/password salah.Gunakan alamat email lengkap dan reset password mailbox bila perlu.
Certificate errorHostname tidak cocok dengan sertifikat.Gunakan hostname SMTP resmi dari hosting, bukan alamat buatan sendiri.
Email masuk SpamReputasi domain atau DNS email belum lengkap.Aktifkan SPF, DKIM, dan DMARC; tandai email sebagai bukan spam.
Tautan mengarah ke localhostAPP_URL atau cache masih lama.Perbaiki APP_URL, PUBLIC_ORIGIN, lalu jalankan optimize:clear.
403 tautan tidak validTautan kedaluwarsa, sudah digunakan, atau domain berubah.Kirim ulang undangan/verifikasi dan buka tautan terbaru.
Email hanya muncul di logMAIL_MAILER masih log.Ubah menjadi smtp dan bersihkan cache konfigurasi.

Periksa log Laravel

Buka file terbaru pada folder storage/logs. Cari kata seperti SMTP, authentication, connection, atau certificate.

storage/logs/laravel.log
Keamanan saat meminta bantuan: kirim pesan error yang relevan, tetapi hapus username, password, token, dan alamat email sensitif sebelum mengirim screenshot.

09 · DNS dan Keamanan

Agar Email Lebih Terpercaya.

SMTP dapat bekerja tanpa pengaturan tambahan, tetapi SPF, DKIM, dan DMARC membantu email tidak dianggap palsu atau masuk Spam.

DNSFungsi
SPFMemberi tahu server penerima bahwa server hosting diizinkan mengirim email untuk domain Anda.
DKIMMemberikan tanda tangan digital pada email untuk membuktikan email tidak diubah.
DMARCMenentukan tindakan ketika email gagal pemeriksaan SPF atau DKIM.
  1. Di cPanel buka Email Deliverability.
  2. Pilih domain website.
  3. Periksa status SPF dan DKIM.
  4. Jika ada peringatan, klik Repair bila DNS dikelola oleh hosting.
  5. Jika DNS dikelola Cloudflare, salin record yang disediakan cPanel ke menu DNS Cloudflare.
  6. Untuk record email, gunakan mode DNS only, bukan proxy Cloudflare.
Catatan: perubahan DNS dapat membutuhkan waktu propagasi. Tunggu beberapa menit hingga beberapa jam sebelum menguji ulang.

Aturan password dan akun

  • Gunakan password SMTP yang berbeda dari password cPanel.
  • Jangan menyimpan file .env di repository publik.
  • Batasi akses File Manager dan SSH.
  • Aktifkan 2FA pada akun hosting.
  • Nonaktifkan akun CMS yang sudah tidak digunakan.

10 · Checklist Production

Pemeriksaan Terakhir.

Hosting

  • Akun email sistem dibuat.
  • SMTP host dan port benar.
  • Password email tersimpan aman.
  • SPF dan DKIM valid.

Environment

  • APP_ENV=production.
  • APP_DEBUG=false.
  • APP_URL memakai HTTPS.
  • MAIL_MAILER=smtp.
  • MAIL_FROM_ADDRESS benar.

Deployment

  • Migrasi sudah dijalankan.
  • Cache konfigurasi dibersihkan.
  • Build frontend terbaru tersedia.
  • Folder storage dapat ditulis.

Pengujian

  • Undangan diterima.
  • Password dapat dibuat.
  • Akun baru dapat login.
  • Email superadmin dapat diganti.
  • Kirim ulang berfungsi.

Perintah deployment ringkas

php artisan migrate --force php artisan optimize:clear php artisan config:cache php artisan route:cache php artisan view:cache
Setup dinyatakan selesai apabila email undangan tiba pada Inbox, tautan aktivasi bekerja, pengguna dapat membuat password, dan status pada Kelola Akses berubah menjadi Aktif & Terverifikasi.
