COSMIC CMS · Product Design

Section
Visibility.

Rancangan fitur untuk menyembunyikan, menampilkan, mengurutkan, mempreview, dan mempublikasikan section website COSMIC dari dashboard admin.

Versi 1.020 Oktober 2026Pekanbaru, Indonesia
01 · Tujuan

Ringkasan Rancangan.

Superadmin dan role yang diberi izin dapat mengatur komposisi setiap halaman publik tanpa mengubah kode. Perubahan disimpan sebagai draft terlebih dahulu agar website aktif tidak berubah secara tidak sengaja.

Keputusan utama: visibilitas dan urutan section dikelola di database. Navbar dan footer merupakan elemen sistem yang selalu tampil pada versi pertama. Isi section belum diedit lewat fitur ini; pengaturan konten menjadi modul lanjutan.

Sasaran

Kontrol

Toggle tampil/sembunyi per section, urutkan dengan drag-and-drop, dan reset ke susunan bawaan.

Keamanan

Draft dan versi terbit dipisahkan, divalidasi, dicatat dalam audit log, serta dibatasi dengan permission.

Konsistensi

Daftar section memakai registry komponen yang telah disetujui; admin tidak dapat menyisipkan komponen arbitrer.

Performa

Konfigurasi publik dicache dan hanya section aktif yang dirender di Vue.

04 · Model Data

Arsitektur Konfigurasi.

page_layouts ├── id ├── page_key // home, schedule, league, team ├── status // draft | published ├── version // integer ├── published_at // nullable ├── published_by // nullable user FK └── timestamps page_sections ├── id ├── page_layout_id // FK ├── section_key // home.next_match ├── label // label dashboard ├── component // registry key, bukan path bebas ├── is_visible // boolean ├── is_locked // hero dapat dikunci ├── sort_order // integer ├── settings // JSON, disiapkan untuk fase editor konten └── timestamps page_layout_audits ├── page_layout_id, user_id, action ├── before_payload, after_payload └── created_at

Registry Frontend

Frontend menggunakan peta komponen statis. Database hanya menyimpan key yang diizinkan, sehingga nama file atau kode tidak pernah dieksekusi dari input admin.

const sectionRegistry = { 'home.hero': HeroSection, 'home.next_match': NextMatchSection, 'home.match_center': MatchCenterSection, // ... } visibleSections .sort((a, b) => a.sort_order - b.sort_order) .map(section => sectionRegistry[section.section_key])

05 · Status & Publikasi

Siklus Perubahan.

Published

Versi yang dibaca pengunjung. Dicache per halaman dan tidak berubah hingga aksi publish berhasil.

Draft

Salinan kerja admin. Dapat disimpan berulang kali, dipreview, dan dibatalkan tanpa memengaruhi publik.

Publish

Validasi registry, duplikasi key, urutan, minimal section, kemudian transaksi database dan invalidasi cache.

Restore

“Batalkan perubahan” mengembalikan draft ke published. Riwayat versi penuh dapat ditambahkan pada fase berikutnya.

Permission yang Diusulkan

PermissionKemampuanDefault
landing.viewMelihat susunan section dan status.Admin + Superadmin
landing.updateMengubah visibilitas, urutan, dan menyimpan draft.Admin + Superadmin
landing.previewMembuka preview draft bertoken.Admin + Superadmin
landing.publishMenerbitkan atau membatalkan draft.Superadmin; dapat didelegasikan

Audit Minimum

Catat pelaku, waktu, halaman, aksi, daftar section yang berubah, nilai sebelum/sesudah, dan versi terbit. Jangan hanya mencatat pesan umum “landing page diperbarui”.

06 · Kontrak Teknis

API & Rendering.

Method & endpointFungsi
GET /admin/pagesDaftar halaman, status draft, dan waktu publish.
GET /admin/pages/{page}Editor section untuk satu halaman.
PUT /admin/pages/{page}/draftSimpan visibilitas dan urutan draft.
POST /admin/pages/{page}/publishValidasi dan terbitkan draft secara atomik.
POST /admin/pages/{page}/discardReset draft dari versi published.
GET /preview/{page}?token=...Preview draft aman dan sementara.

Payload Draft

{ "sections": [ { "key": "home.hero", "visible": true, "order": 10 }, { "key": "home.next_match", "visible": true, "order": 20 }, { "key": "home.match_center", "visible": false, "order": 30 } ] }

Strategi Rendering Publik

  1. Controller mengambil konfigurasi published dari cache.
  2. Inertia mengirim daftar key aktif dan urutannya ke page Vue.
  3. Vue menyaring registry lalu merender komponen sesuai urutan.
  4. Jika konfigurasi belum tersedia, fallback memakai urutan bawaan saat ini.
  5. Section tidak aktif tidak dibuat di DOM, sehingga GSAP/ScrollTrigger tidak mengikat animasi yang tidak digunakan.

07 · Aturan & Kualitas

Kriteria Penerimaan.

  • Admin berizin dapat menyembunyikan section dan perubahan belum terlihat publik sebelum publish.
  • Urutan section dapat diubah dengan drag-and-drop serta tombol naik/turun untuk aksesibilitas.
  • Navbar dan footer tetap tampil meskipun seluruh section opsional disembunyikan.
  • Preview menampilkan draft terbaru dan tidak mengubah cache publik.
  • Publish berjalan dalam transaksi dan tidak menghasilkan halaman setengah terbarui.
  • Role tanpa landing.update tidak dapat memanggil endpoint update secara langsung.
  • Section key yang tidak terdaftar ditolak oleh validator.
  • Tampilan editor berfungsi pada desktop dan smartphone.
  • Publik tetap memakai susunan bawaan apabila data konfigurasi rusak atau belum disiapkan.
  • Setiap publish menghasilkan audit yang dapat ditelusuri.

Risiko dan Mitigasi

RisikoMitigasi
Admin menyembunyikan konten penting.Section wajib dikunci, dialog konfirmasi, preview, dan fallback.
Komponen lama bergantung pada posisi DOM.Uji GSAP/ScrollTrigger per halaman setelah filtering dan reorder.
Draft menimpa perubahan admin lain.Optimistic locking dengan version/updated_at dan pesan konflik.
Cache menampilkan versi lama.Invalidasi cache hanya setelah transaksi publish berhasil.
Hak akses hanya disembunyikan di UI.Middleware permission wajib pada seluruh endpoint mutasi.
Dokumen ini menjadi spesifikasi rancangan V1. Detail editor konten section dibahas sebagai fitur terpisah agar scope visibilitas tetap terukur.
