Editor.

Rancangan editor konten dinamis untuk mengubah teks, gambar, tautan, daftar, statistik, pemain, pertandingan, sponsor, dan pengaturan tampilan setiap section.

Dokumen 02Versi 1.0 · 20 Oktober 2026Pekanbaru, Indonesia
01 · Tujuan

Ringkasan Rancangan.

Setiap section memiliki editor berdasarkan schema yang terkontrol. Admin mengubah draft, mempreview hasil, lalu pengguna berizin menerbitkannya tanpa menyentuh kode Vue.

Prinsip utama: komponen Vue tetap menjadi sumber struktur visual, sedangkan database menjadi sumber konten. Schema menjadi kontrak yang memastikan hanya data yang dikenal komponen yang dapat disimpan.

Reusable

Satu mesin form menangani teks, angka, media, relasi, repeater, dan JSON tanpa membuat halaman form baru per section.

Aman

Field dibatasi schema, divalidasi backend, memiliki draft/published, permission, dan audit.

Konsisten

Admin hanya memilih variasi tampilan yang sudah disetujui. Tidak tersedia CSS atau kode bebas.

Terukur

Konten sederhana dan data operasional seperti pemain/pertandingan dipisahkan menurut sumber datanya.

Ruang Lingkup

TermasukLanjutan
Schema editor, draft/publish, migrasi current data, upload media, preview, validasi, audit, field dasar, data kompleks terstruktur.Rich-text penuh, crop gambar interaktif, workflow persetujuan bertingkat, penjadwalan publish, multibahasa, rollback multi-versi.

02 · Current Data

Migrasi Konten Awal.

Masalah yang ditemukan: tampilan publik masih memperoleh current data dari default props dan konstanta di komponen Vue, sementara record draft/published dibuat kosong. Akibatnya editor tidak menampilkan konten yang sedang terlihat.

Alur Migrasi yang Benar

Default Vue saat ini→Default Content Registry→Published Content→Draft Content→Form Editor
Prioritas bacaSumberTujuan
1Draft contentNilai terbaru dalam editor dan preview.
2Published contentNilai aktif bila draft belum memiliki override.
3Default content registryFallback saat database belum memiliki nilai.
4Default props komponenJaring pengaman terakhir, bukan sumber utama CMS.

Aturan Seed

  • Seeder mengisi current data hanya ketika section belum memiliki content record.
  • Seeder berikutnya tidak boleh menimpa hasil edit admin.
  • Default registry dan props Vue harus memiliki bentuk data yang sama.
  • Data pemain, pertandingan, klasemen, staf, dan sponsor ikut dimigrasikan.

Schema Contoh

'home.hero' => [ 'titleTop' => ['type' => 'text', 'max' => 80], 'description' => ['type' => 'textarea', 'max' => 1200], 'backgroundImage' => ['type' => 'media'], 'primaryHref' => ['type' => 'url'], ]

Frontend dan backend membaca schema yang sama secara konseptual. Backend tetap menjadi otoritas validasi.

05 · Sumber Data

Tiga Kategori Section.

Konten Manual

Hero, Club Culture, Tentang COSMIC, CTA, Competition Rules, Captain Spotlight.

Konten disimpan sebagai versioned section content.

Berbasis Modul

Next Match, hasil pertandingan, daftar pemain, top players, klub peserta, sponsor.

Editor memilih record dari CRUD sumber; tidak menduplikasi data.

Statistik

Ringkasan musim, performa, statistik skuad, komposisi posisi.

Mendukung mode otomatis dan override manual.

Display Settings

Jumlah item, filter musim, orientasi gambar, tema, dan alignment.

Hanya variasi desain yang telah disetujui.

Keputusan untuk Data Kompleks

JSON boleh digunakan sebagai format penyimpanan internal, tetapi bukan pengalaman akhir admin. Data berulang harus diedit melalui repeater visual; pemain dan pertandingan melalui relation picker.

Contoh: section “Player of the Month” tidak menyimpan ulang nama dan foto pemain. Section menyimpan player_id, periode, narasi, dan statistik bulan tersebut.

06 · Data & Publikasi

Versioning Konten.

section_content_versions ├── id ├── page_section_id ├── status // draft | published ├── version ├── content // JSON tervalidasi schema ├── created_by ├── published_by ├── published_at └── timestamps
Edit→Validasi Schema→Simpan Draft→Preview→Publish→Clear Cache

Aturan Publikasi

  • Draft konten dan draft layout dipreview dalam satu versi halaman.
  • Publish menyalin seluruh draft section menjadi published dalam transaksi database.
  • Jika satu section gagal divalidasi, seluruh publish dibatalkan.
  • Audit menyimpan section key dan perubahan sebelum/sesudah.
  • Discard mengembalikan visibilitas, urutan, dan konten draft ke versi published.

07 · Media & Preview

Media Library.

Upload

JPG, PNG, dan WebP dengan batas ukuran, validasi MIME, nama file aman, dan folder berdasarkan penggunaan.

Metadata

Alt text, dimensi, ukuran file, focal point, uploader, waktu unggah, dan penggunaan.

Picker

Cari, filter, preview, pilih media lama, atau upload baru tanpa keluar dari editor.

Proteksi

Media yang sedang dipakai tidak dapat dihapus sebelum relasinya dilepas.

Dua Tingkat Preview

PreviewTujuan
Section PreviewUmpan balik cepat dalam editor dengan pilihan desktop, tablet, dan smartphone.
Page PreviewMemeriksa interaksi section, jarak, GSAP, navigasi, dan keseluruhan halaman.
Catatan animasi: perubahan konten dapat mengubah tinggi elemen. Setelah render preview, ScrollTrigger harus direfresh agar posisi animasi tetap akurat.

08 · Kualitas

Kriteria Penerimaan.

  • Editor pertama kali dibuka menampilkan current data yang sama dengan website, bukan form kosong.
  • Draft tidak terlihat oleh pengunjung sebelum publish.
  • Field yang tidak terdaftar schema ditolak.
  • Format JSON rusak, URL tidak valid, dan media melebihi batas menghasilkan pesan field yang jelas.
  • Data berulang dapat ditambah, diurutkan, dan dihapus melalui repeater visual.
  • Preview menggunakan draft terbaru dan tersedia pada viewport desktop/mobile.
  • Publish memperbarui konten dan cache secara atomik.
  • Discard memulihkan seluruh draft dari published.
  • Role tanpa permission tidak dapat menggunakan endpoint secara langsung.
  • Komponen Vue tetap mempunyai fallback aman ketika content record belum tersedia.

Urutan Implementasi

Current Data Migration→Field Engine→Media Picker→Repeater & Relations→Preview→Publish & Tests
